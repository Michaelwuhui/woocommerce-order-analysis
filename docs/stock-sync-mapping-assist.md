# 跨站库存同步中的商品映射建议

在产品管理 → 跨站库存同步完成来源和目标站选择后，使用“3.1 · 补齐商品映射”。系统读取参照站和所选目标站的完整目录，展示已有绑定、明确匹配、需要人工核对的建议以及没有 SKU 候选的商品。系统设置底部“未识别产品”也提供入口。

SKU、条码、完整名称用于精确匹配；已有产品分类映射和品牌别名、系列、口数、口味解析用于生成候选。产品名称解析与原系统共享 `product_recognition.py`，不会另行维护一套品牌规则。多个候选、标识与名称/口味冲突，以及一个 WC SKU 被多个商品使用时，不能通过“选择明确匹配”自动选中。

操作人员可以批量选择明确匹配，也可在同页调整 SKU 和每件折合数量。所有新绑定都需要明确勾选、核对口味/规格/数量并填写操作原因。没有 SKU 主档的商品会提示先建档，不自动创建库存或猜测供货仓。

建议读取和确认核实由现有 worker 队列处理。确认前会重新读取商品身份，检查最新权限、站点配置、SKU 主档和识别规则。所有选中记录在同一数据库事务中保存；已有不同绑定导致整批不保存，已有相同绑定视为原已一致。相同确认内容重复提交返回同一个任务，审计记录包含操作人、原因、源建议和具体绑定。

补齐映射需库存管理权限，且只能保存本人有权操作的站点。共享参照站的只读权限不会变成映射写权限。读取及确认映射只使用 WooCommerce GET，不改网站库存、商品内容、仓库库存、供货关系或主子站能力授权。

保存成功后，库存同步目录自动重读，按站点/商品/变体身份保留原选择，旧库存预览失效。新的映射需经过正常的库存差异预览及执行确认；主子站范围、供货来源、包装可比性和库存保护仍照常检查。

实现复用现有 `stock_sync_catalog_snapshots`、`stock_sync_work`、`stock_sync_events`，新增队列类型 `mapping` / `mapping_confirm`，不需要数据库结构迁移。发布时应在队列空闲时先更新 worker，再更新 Web；回滚前应等待这两种任务处理完毕。刷新同一页面时会恢复已提交的映射确认进度。
